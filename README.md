# Late-order root cause: is it the carrier, or the promise?

A SQL analysis of why orders arrive after their required date, with data checks and a what-if.

**Finding.** Carrier, employee, ship-to country, month and weekday explain almost none of the variation in late deliveries. The lead time promised to the customer explains nearly all of it: orders promised in a week or less are 23% of volume but 64% of late orders. A minimum-promise what-if shows how the late rate would fall if short promises were lengthened.

**Live report:** https://d00042.github.io/late-order-root-cause/

## Run it

```bash
python run.py     # downloads northwind.db on first run (about 25 MB), writes index.html and results.json
```

Python 3.8+, standard library only.

## What is in the repo

| File | Purpose |
| --- | --- |
| `queries.sql` | Named, commented SQL: data checks, late rate overall, by lead time and by five other factors, shipping-time distribution |
| `run.py` | Loads the queries, runs them on SQLite, computes spreads and the what-if, writes the report |
| `index.html` | The report, regenerated by `run.py` |
| `results.json` | The computed numbers behind the report |

## Method notes

- An order is late when its shipped date is after its required date. Dates are normalised with `date()` because the source mixes plain dates and timestamps (flagged in the data checks).
- Segments under 100 orders are ignored when comparing factors, since their rates are mostly noise.
- The what-if assumes shipping time does not depend on the promise (the report checks this) and ignores commercial effects of longer promises.

## Data

The enlarged community version of Microsoft's Northwind sample database, a fictional trading company: https://github.com/jpwhite3/northwind-SQLite3. It is a teaching dataset, so this is a worked method, not a finding about a real business. The lateness pattern is partly mechanical: an order is late when shipping takes longer than promised.
